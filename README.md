# CS-360

The requirements and goals of my app were centered on building an event scheduling tool that would help users keep track of their tasks, dates, and reminders. From the beginning, the main need I wanted to address was helping people stay organized without making the app overly complex. Many struggle with managing their time or remembering commitments, so I designed the app to be simple but functional, giving users an easy way to log in, manage events, and receive notifications about upcoming deadlines. That goal drove every decision in the project.

To support those needs, I built several key screens and features. The login screen allowed users to securely access or create accounts, while the grid-style data display gave them a clear overview of scheduled events. Buttons for adding, updating, or deleting entries kept users in control of their schedules, and the SMS screen handled permissions and reminders. Throughout the UI design, I focused on clarity and flow. I ensured that labels were clear, buttons were easy to spot, and the layout was intuitive. These choices prioritized usability and reduced confusion, especially for new users.

My coding approach was step-by-step: I started with the login functionality, then built the database shell, and finally added SMS permissions and notifications. Breaking the work into manageable parts made development less overwhelming and easier to test as I went. Consistent naming conventions and inline comments kept my code organized and understandable. These are habits I know will help me in future projects.

Testing played a big role in ensuring the app functioned correctly. Using the Android Emulator, I simulated scenarios like logging in, adding events, or denying SMS permissions. Testing revealed issues such as incorrect listeners or permission checks, which helped me understand how my code connected to the UI. One of the biggest challenges was handling SMS permissions; at first, it was intimidating to make the app function whether access was granted or denied. Through extra research, testing, and conditional logic, I created a smoother experience that respected user choices. This pushed me to think more critically about design and functionality.

The component I feel most successful with was the database shell and grid display. This feature tied together many skills which included working with SQLite, designing a clear UI, and implementing CRUD operations so users could manage entries easily. Getting this functionality to work boosted my confidence because it showed I could connect backend database logic with the frontend interface in a meaningful way. More than just writing code, it demonstrated my ability to build tools that manage and present user data effectively.
